# 视频生成工具剖析 · 与奶龙讲解视频的合并

> 2026-10-22 · 读了 HyperFrames、Remotion、Manim、remotion-video-skill、video-shotcraft 的 README / SKILL 契约后整理。
> 目标：把「它们怎么做出视频」讲成小学生能懂的话，再合并成奶龙自己的做法。

---

## 一、先看共同点：大家其实都在做同一件事

不管工具长什么样，做视频只有四步：

1. **写剧本**：这一秒画面里有什么、下一秒变成什么。
2. **搭场景**：图形、文字、图片、数学公式，摆好位置。
3. **按时间演**：给每个东西一个「几点出现、演多久、怎么动」。
4. **拍下来**：一帧一帧截图，再把截图和声音粘成 MP4。

差别只在第 2、3 步「用什么语言描述」，以及第 4 步「怎么保证每次拍出来都一样」。

打个比方：
- **Manim** 像一位数学老师，在黑板上用粉笔一笔一笔写出公式，还会让公式自己变形。
- **Remotion** 像乐高：用 React 组件拼画面，每个组件的状态由「现在是第几帧」决定。
- **HyperFrames** 像拍定格动画：先把整条时间轴暂停，再把时间拨到第 0 帧、第 1 帧、第 2 帧……逐帧拍照。
- **video-shotcraft** 像电影摄影指导：不发明画面，而是从「镜头配方卡」里挑运镜，卡着音乐节拍剪。
- **remotion-video-skill** 像流水线工人：先配音，量出每句话多长，再按语音长度排场景。

## 二、逐个拆开看

### 1. Manim（3Blue1Brown 的动画引擎）

**一句话**：用 Python 描述「数学对象怎么变」，引擎帮你补出中间每一帧。

核心零件：
- **Mobject**：能画的东西（圆、线、公式、文字）。
- **Animation**：动作（Create 画出来、Write 写字、Transform 变形、FadeIn 淡入、Indicate 指一下）。
- **Scene**：舞台，`self.play(A, B)` 就是「同时演 A 和 B」。
- **alpha**：每个动作其实是 0→1 的进度条；引擎按 alpha 算出对象每一帧的位置/形状/透明度。

**为什么好看**：它动的是「意义」——公式从一行变成另一行，三角形的高落下来，坐标系里的点沿曲线走。不是幻灯片切换。

**奶龙能抄的**：公式不是一张图，而是「一行一行写出来、旧行变灰、新行高亮」；几何图不是静态 SVG，而是边长、角度逐步标注。

### 2. Remotion（用 React 写视频）

**一句话**：视频就是一个网页，每一帧都是这个网页在某个时刻的样子。

核心零件：
- **Composition**：一段视频（宽高、帧率、总帧数）。
- **useCurrentFrame()**：当前第几帧；组件根据它决定透明度/位置。
- **Sequence / Series**：把镜头按时间排好，谁先谁后。
- **renderMedia**：用无头 Chrome 一帧一帧截图，再用 ffmpeg 合成；`renderStill` 只截一帧用来检查。

**关键思想**：**确定性**——同一帧号永远画出同一画面（不许用 `Date.now()`、随机数要固定种子）。所以能断点续渲、能只重渲一个镜头、能抽帧验收。

**奶龙能抄的**：奶龙已经是「HTML + 逐帧截图 + ffmpeg」，和 Remotion 同构；缺的是**组件库**和**抽帧自检**。

### 3. HyperFrames（HTML 直接变视频）

**一句话**：写普通 HTML/CSS，给每个元素标上「第几秒开始、演多久」，然后把时间轴暂停、逐帧 seek 拍照。

契约里最值钱的几条（原文精简）：
- 每个有时间行为的元素都要 `data-start` / `data-duration`，并且**在结束前落到终态**。
- 画面里的一切都必须**是时间轴时间的函数**：禁止 `Date.now()`、无种子随机、网络请求、定时器、无限循环动画。
- 不要对 `display/visibility` 做补间；不要用 CSS transform 和动画库抢同一个元素。
- 先 `check`（静态检查）→ 再 `snapshot`（抽帧看）→ 最后 `render`；超 15 秒的故事片要先写三种故事线。
- 有 450 个现成积木（转场、字幕、标题、图表、3D、运镜），**先找再自己写**。

**奶龙能抄的**：clip 契约（每个元素带起止时间）+ 渲染前 lint + 抽帧 review；以及「先查积木库」的习惯。

### 4. video-shotcraft（镜头配方卡 + 电影感）

**一句话**：不生成画面，而是把你产品**真实的页面截图**放进 124 张「镜头配方卡」里，用 Remotion 动起来，卡着音乐节拍剪，最后抽帧验收。

九条理念里最狠的：
- 复刻真实页面必须用**真实截图**，不许手搓假 UI；手搓只用于抽象段落，且必须够高级。
- 视觉语言必须**从产品自己的设计系统长出来**（字体、色板、间距、圆角），不能套一层不相干的「宣传片皮肤」。
- 电影感来自**运镜、光影、节奏、声音**，不来自堆特效；批量元素靠运动入场，不靠逐个发光。
- **一个镜头只讲一个动效**；关键信息落定后必须**呼吸**（字标停 ≥1 秒，批量动效后留 0.5 秒静止）。
- 强节奏 BGM：先做节拍分析，转场卡在拍子上；整画面冲击全片 ≤3 次。
- **确定性渲染**：禁 `Date.now()`/`Math.random()`，伪随机固定种子，逐帧可复现。
- 验收贯穿全程：每个镜头 `remotion still` 出静帧自检，交付前派**干净上下文的 subagent** 独立终检。

**奶龙能抄的**：镜头配方卡（把「讲解一步」变成「一个有名字的镜头」）、呼吸节奏、独立终检、真实解题卡截图入镜。

### 5. remotion-video-skill（配音驱动的流水线）

**一句话**：先让 TTS 把旁白念出来，量出每段音频多长，再按音频长度排画面；带字幕和音乐可视化。

**奶龙能抄的**：奶龙已经是这条路线（TTS → 时长 → 时间轴）；可以再进一步做**逐句字幕**和**卡语音节拍**。

## 三、五个工具对照表

| 维度 | Manim | Remotion | HyperFrames | shotcraft | 奶龙现状 |
|---|---|---|---|---|---|
| 描述语言 | Python 对象 | React 组件 | HTML + data-* | 镜头卡 + Remotion | JSON 分镜 + HTML 模板 |
| 时间模型 | 动作 alpha | 帧号 | 暂停时间轴 seek | 帧号 + 拍点 | 毫秒时间轴 |
| 渲染 | Cairo/OpenGL→ffmpeg | 无头 Chrome→ffmpeg | 无头 Chrome→ffmpeg | 无头 Chrome→ffmpeg | 隐藏窗口截图→ffmpeg |
| 确定性 | 是 | 强约束 | 写进契约 | 写进理念 | 基本是（视觉由 ms 驱动） |
| 组件/积木 | Mobject | React 组件 | 450 积木 | 124 镜头卡 | 6 种 SVG 图示 |
| 自检 | 手动 | still | check + snapshot | still + 独立终检 | 无 |
| 声音 | 可加 | `<Audio>` | `<audio>` 独立轨 | SFX + BGM + 卡拍 | TTS 旁白 |

**结论**：奶龙的引擎和它们同构，差三样东西——**镜头词汇表**、**确定性契约**、**自检闭环**。

## 四、合并后的新流水线（奶龙 2.1「导演版」）

```
题目/知识点
  ↓ ① 讲解卡（已有，SymPy 验算 + 图示 + 直觉/比喻）
  ↓ ② 导演层：把解题步骤翻译成「镜头列表」
       每镜 = 一个镜头类型 + 时长 + 旁白 + 图示 + 呼吸时间
  ↓ ③ 渲染层：seekable HTML（每个元素 data-start/duration）+ 逐帧截图
  ↓ ④ 音频层：TTS 旁白 + 字幕分句 + 尾音留白
  ↓ ⑤ 质检层：渲染前 lint + 抽帧 still + 交付说明
  ↓ ⑥ 产物：MP4 ＋ 可交互讲解页（同一份讲解卡）
```

### 镜头类型（从 6 种扩到 10 种）

| 镜头 | 干什么 | 来自谁 |
|---|---|---|
| `triangle` | 几何图 | 已有 |
| `axes` | 坐标系/函数 | 已有 |
| `vectors` | 受力/向量 | 已有 |
| `flow` | 步骤流程 | 已有 |
| `circle` / `numberline` | 圆/数轴 | 已有 |
| **`formula`** | 公式逐行写出、旧行变灰、新行高亮、可变形 | Manim |
| **`board`** | 黑板式逐步推导，带「粉笔」下划线 | Manim |
| **`spotlight`** | 一句话直觉/生活比喻，聚光卡片 | shotcraft |
| **`camera`** | 任意图示的缓慢推近/平移（Ken Burns） | shotcraft |
| **`compare`** | 两栏对照（错解 vs 正解） | 自创 |

### 节奏规则（写死进代码）

- 每镜最短 2.6 秒，旁白后至少留 0.7 秒呼吸。
- 关键结论落定后额外停 0.8 秒。
- 全片「大冲击」（整屏闪烁/推近）不超过 3 次。
- 一个镜头只讲一件事；同一动效全片只当一次主角。

### 质检清单（渲染前 + 渲染后）

- lint：每镜有没有旁白、有没有图示、bullet 是否超长、总时长是否超 8 分钟。
- still：抽 3 帧（开头/中间/结尾）人工看一眼。
- 交付：视频路径 + 时长 + 镜头数 + 用了哪些镜头类型。

## 五、想出来的几个「可能让人眼前一亮」的点子

1. **公式会变形（Manim 的核心快感）**
   不是把公式当图片，而是让 `x² = 4` 直接在原位置变成 `x = ±2`，中间的 `−4`、开方过程逐行浮现。观众看到的是「推理在发生」，不是「PPT 翻页」。

2. **讲解页会长大**
   同一个讲解卡先生成可点的 HTML 页面，再让一台「摄像机」在页面里缓慢推近、平移、掠过某个步骤——视频就是讲解页的「航拍」。一份内容，两种形态，0 额外 token。

3. **错题复习短片**
   到期的错题自动拼成 30 秒短片：一题 5 秒，先亮题、再亮关键一步、最后亮答案和「你上次错在哪」。间隔复习 + 视频，比列表有仪式感。

4. **会呼吸的字幕**
   旁白按句切分，字幕逐句出现、旧句淡出；关键词加粗变色。不是整段旁白糊在底部。

5. **抽帧自检 + 独立终检**
   渲染完自动抽 3 帧图，交给一个「没参与制作」的审片 agent 看：有没有文字出界、图示和旁白对不上、节奏太赶。有问题的镜头单独重渲——因为渲染是确定性的，重渲一镜不影响别的。

6. **确定性渲染 = 免费的可编辑性**
   每个镜头存成独立文件后，用户可以只改第 3 镜的旁白再重渲，其他镜头直接复用。这就是 Remotion/shotcraft 敢叫「fully editable」的底气。

7. **声音设计的最小版**
   转场时一个很轻的「叮」、答案揭晓时一个上扬音效。不做 BGM 卡拍（教学视频里 BGM 容易吵），但保留「关键节点有声音」的仪式感。
